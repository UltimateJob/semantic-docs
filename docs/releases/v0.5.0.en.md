## Scope

The v0.5.0 spine is the **MuJoCo product chain**: a vertical loop from conversational planning to real Robot Skill physical execution, plus matching type-package Bundles, installer, and Gate toolchain. The Framework development branch is `feature/robot-ability-binding`; semantic-robot-deployment uses `feature/v050-r1pro-runtime-bundle`. (Source: branch mapping in quick-start/installer-settings.json)

## Added

- Pilot device execution spine: Server-to-multi-Pilot execution, automatic Semantic Server discovery, simpler device join and Skill desired-state convergence; Studio shows the Robot device workbench and Runtime readiness. (Source: semantic-framework @da69033, @93481a6, @acb016c; semantic-web @f2edad9, @27f8ac7, @835e6e0)
- Managed MuJoCo Robot lifecycle: robot-runtime starts, stops, and reports online state for managed simulated Robots; Project unifies resource and Runtime selection. (Source: semantic-framework @5b38e50, @0cc7ec4, @1edf67d, @abb2a2d; semantic-web @1584f67)
- Robot Skill manual debug: Pilot local debug entry and Studio Robot Skill debug panel, including terminal state and failure reasons. (Source: semantic-framework @3c79c25, @f2cd00c; semantic-web @03c0af4, @fb6e088)
- Multi-Agent task message aggregation and Interaction cancel: Conversation aggregates task messages, shows wait context, and can cancel a question and restore the original Agent. (Source: semantic-framework @2256442, @0673ad8; semantic-web @44f7b59, @f884c81)
- Depalletizing product chain: Project depalletizing planning Skills, deterministic dispatch of planned Robot Skills, and a closed real-Agent depalletizing execution chain; Robot Skills complete single- and dual-side loops; Abilities close dual-side grasp/place and live observation. (Source: semantic-framework @6222428, @cad0154, @827d62f; semantic-skill/robot-skill @21ed2d6, @052009f; semantic-ability/r1pro-ability @e5c84f4)
- Type packages and Robot Bundles: `r1pro-mujoco` and `r1pro-fake` RobotRuntimeBundle type packages (`apiVersion: semantic.insightos.cn/v1alpha1`) pin exact Wheel versions for Robot SDK, AbilityFramework, Ability, and Robot Skill SDK. (Source: semantic-robot-deployment @251422b, @9a43aad, @247b7c8; type-package `bundle.yaml`, `metadata.version: 0.5.0-dev`)
- v050 Gate and artifact toolchain: `test-v050-real-gate`, `test-v050-mujoco-product`, `test-v050-mujoco-deepseek-single`, `refresh-v050-mujoco-bundle`, `publish-v050-mujoco-skills`, `perf-baseline`. (Source: semantic-framework/Makefile `VERSION ?= 0.5.0-dev` and v050 targets)
- One-click installer: `quick-start/semantic_installer.py` TUI installer covering join codes, startup, Bundle swap, and stopping old services before a Bundle change. (Source: quick-start @e6c8f9f, @de32c28, @c885f44)
- LLM endpoint call parameters: default-value protection and truncated auto-continue; Studio endpoint cards can view and edit call parameters. (Source: semantic-framework @cca62b7; semantic-web @e3244e1)
- AbilityFramework in-repo and Wheel cache: AbilityFramework source builds wheels, with an r1pro-mujoco third-party Wheel cache; urdfdom cache corrected 6.0 → 4.0 to match pinocchio 3.9.0. (Source: semantic-ability/ability-runtime @a28273c, @1ea7999)

## Breaking changes

- Removed old Workflow compatibility paths and old RobotStart wiring; Web removed old Proposal generation and Task compatibility. Integrations that depended on the old Proposal/RobotStart APIs break. (Source: semantic-framework @75efc42, @82f0fb4; semantic-web @07ced36)
- Robot Skill SDK separated from Skill packages: runtime SDK is the `semantic-robot-skill-sdk` Wheel (0.1.0.dev0); Skill packages install through Registry and Pilot initializes the Skill Worker. (Source: semantic-skill/robot-skill @a1ccb25, @e8411e4, @0f8773b)
- Robot SDK is determined by the type package referenced by RobotDeployment. (Source: semantic-robot-deployment @6a0a5f1)
- Bundle Wheel dependencies tightened: robot-skill bundle Wheels align to pydantic 2.13.4; the offline MuJoCo WebSocket Wheel is required. (Source: semantic-skill/robot-skill @5ba6f55; semantic-robot-deployment @2daae21)

## Configuration migration

- Pilot dispatches the full RobotDeployment configuration. Deploy templates come from the type package `templates/robot-deployment.yaml.tmpl`. (Source: semantic-framework @e897d77; type-package templates)
- Default ports (quick-start installer presets): Server HTTP `8080`, Pilot WebSocket `8081` (`/ws/pilot`), Web `3000`, plugin-mujoco `8090`, Ability port range `18100-18199`. (Source: quick-start/installer-settings.json)
- Stop old services before swapping a Bundle. The installer does this; for a manual `refresh-v050-mujoco-bundle`, stop the Scene/Server or pass `--stop-users`. (Source: quick-start @de32c28)

## Action Schema changes

- Robot Task planning contracts tightened; unschedulable Robot capability descriptions are rejected. (Source: semantic-framework @6356dff, @ceae5c5, @e137934)
- Skill input prechecks on Framework and model-derived input prechecks in the robot-skill SDK. (Source: semantic-framework @0c1f438; semantic-skill/robot-skill @ae28f5e)
- Live observation contract: Ability publishes the 0.4.0 live-state contract; Runtime reports raw tool sensing and unified scene geometry only. (Source: semantic-ability/r1pro-ability @ab04f30; semantic-simulation/mujoco-runtime @0396e35, @d00e63a; semantic-skill/robot-skill @66d9aa8)
