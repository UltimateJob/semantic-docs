## 本版本范围

v0.5.0 的主线是 **MuJoCo 产品链**：从对话规划到 Robot Skill 真实物理执行的纵向闭环，以及配套的类型包 Bundle、安装器和 Gate 工具链。Framework 主开发分支为 `feature/robot-ability-binding`，semantic-robot-deployment 主分支为 `feature/v050-r1pro-runtime-bundle`。（来源：quick-start/installer-settings.json 中各仓分支映射）

## 新增

- Pilot 设备执行主链：Server 到多 Pilot 设备的执行主链打通，Pilot 支持自动发现 Semantic Server、简化设备加入与 Skill 期望状态收敛；Studio 展示 Robot 设备工作台与 Runtime 就绪状态。（来源：semantic-framework @da69033、@93481a6、@acb016c（2026-08-10~08-15）；semantic-web @f2edad9、@27f8ac7、@835e6e0）
- 受管 MuJoCo Robot 生命周期：robot-runtime 接入并收口受管仿真 Robot 的启动、停止与在线状态；Project 内统一资源与 Runtime 选择。（来源：semantic-framework @5b38e50、@0cc7ec4、@1edf67d、@abb2a2d（2026-08-16~08-19）；semantic-web @1584f67）
- Robot Skill 人工调试入口：Pilot 增加本地 Robot Skill 调试入口，Studio 增加 Robot Skill 人工调试面板，支持调试终态与失败原因展示。（来源：semantic-framework @3c79c25、@f2cd00c（2026-08-17）；semantic-web @03c0af4、@fb6e088）
- 多 Agent 任务消息聚合与 Interaction 取消：对话流聚合多 Agent 任务消息，展示任务等待上下文；支持取消询问并恢复原 Agent。（来源：semantic-framework @2256442、@0673ad8（2026-08-20）；semantic-web @44f7b59、@f884c81）
- 拆码垛产品链：Project 拆码垛规划技能、确定性下发已规划的 Robot Skill、真实 Agent 拆码垛执行链收口；Robot Skill 完成单双侧拆码垛闭环；Ability 收口双侧抓取放置与实时观测。（来源：semantic-framework @6222428、@cad0154、@827d62f（2026-08-19~08-28）；semantic-skill/robot-skill @21ed2d6、@052009f；semantic-ability/r1pro-ability @e5c84f4）
- 类型包与 Robot Bundle：新增 `r1pro-mujoco` 与 `r1pro-fake` 两个 RobotRuntimeBundle 类型包（`apiVersion: semantic.insightos.cn/v1alpha1`），Bundle 内固定 Robot SDK、AbilityFramework、Ability、Robot Skill SDK 的精确 Wheel 版本。（来源：semantic-robot-deployment @251422b（2026-08-11）、@9a43aad、@247b7c8；type-packages/r1pro-mujoco/bundle.yaml、type-packages/r1pro-fake/bundle.yaml，`metadata.version: 0.5.0-dev`）
- v050 Gate 与制品工具链：`test-v050-real-gate`（真实 AbilityFramework + Server + Pilot + Fake Robot 纵向验收）、`test-v050-mujoco-product`（原生 MuJoCo 单箱产品链）、`test-v050-mujoco-deepseek-single`（真实 DeepSeek 模型链）、`refresh-v050-mujoco-bundle`（重建并激活 MuJoCo Bundle）、`publish-v050-mujoco-skills`（发布 Skill 产物）、`perf-baseline`。（来源：semantic-framework/Makefile `VERSION ?= 0.5.0-dev` 及 v050 目标定义）
- 一键安装器：`quick-start/semantic_installer.py` 提供 TUI 安装器、运行截图与实战注意事项，覆盖取码、启动、Bundle 更换与换 Bundle 前停旧服务。（来源：quick-start @e6c8f9f、@de32c28、@c885f44（2026-08-29~09-02））
- LLM 端点调用参数：端点调用参数默认值保护与截断自动续写；Studio 端点卡片支持调用参数查看与编辑。（来源：semantic-framework @cca62b7（2026-09-03）；semantic-web @e3244e1）
- AbilityFramework 落仓与 Wheel 缓存：AbilityFramework 源码入仓并构建 wheels，附 r1pro-mujoco 第三方 Wheel 缓存；修正缓存中 urdfdom 6.0→4.0 以匹配 pinocchio 3.9.0。（来源：semantic-ability/ability-runtime @a28273c（2026-08-28）、@1ea7999（2026-08-29））

## 破坏性变化

- 清理旧 Workflow 兼容代码：删除旧 Workflow 兼容路径与旧 RobotStart 接线；Web 端移除旧 Proposal 生成与 Task 兼容路径。依赖旧 Proposal/RobotStart 接口的集成代码失效。（来源：semantic-framework @75efc42（2026-08-15）、@82f0fb4（2026-08-20）；semantic-web @07ced36）
- Robot Skill SDK 与 Skill 包分离：runtime SDK 独立为 `semantic-robot-skill-sdk` Wheel（0.1.0.dev0），Skill 包经 Registry 安装、由 Pilot 初始化 Skill Worker。（来源：semantic-skill/robot-skill @a1ccb25、@e8411e4、@0f8773b（2026-08-09~08-11））
- Robot SDK 由类型包确定：部署侧不再单独选择 SDK，由 RobotDeployment 引用的类型包决定。（来源：semantic-robot-deployment @6a0a5f1 "由类型包确定Robot SDK"，2026-08-15）
- Bundle Wheel 依赖收紧：robot-skill bundle Wheel 对齐 pydantic 2.13.4；离线 MuJoCo WebSocket Wheel 为必选。（来源：semantic-skill/robot-skill @5ba6f55（2026-09-01）；semantic-robot-deployment @2daae21（2026-08-11））

## 配置迁移

- RobotDeployment 对齐完整配置：Pilot 按 RobotDeployment 完整配置下发，部署模板由类型包 `templates/robot-deployment.yaml.tmpl` 提供。（来源：semantic-framework @e897d77（2026-08-16）；semantic-robot-deployment/type-packages/r1pro-mujoco/templates/）
- 默认端口（quick-start 一键安装器预设）：Server HTTP `8080`、Pilot WebSocket `8081`（`/ws/pilot`）、Web `3000`、plugin-mujoco `8090`、Ability 端口段 `18100-18199`。（来源：quick-start/installer-settings.json；semantic-simulation/mujoco-runtime 文档示例）
- 换 Bundle 前先停旧服务：安装器已内置；手工执行 `refresh-v050-mujoco-bundle` 前需停场景/Server 或加 `--stop-users`。（来源：quick-start @de32c28；semantic-framework/Makefile refresh-v050-mujoco-bundle 注释）

## Action Schema 变化

- Robot Task 规划契约收敛：拆码垛计划与任务规划契约收紧，拒绝不可调度的 Robot 能力描述。（来源：semantic-framework @6356dff、@ceae5c5、@e137934（2026-08-19~08-20））
- Skill 输入预检：Framework 侧增加 Skill 输入预检；robot-skill SDK 增加模型派生输入预检。（来源：semantic-framework @0c1f438（2026-08-20）；semantic-skill/robot-skill @ae28f5e）
- 实时观测契约：Ability 发布 0.4.0 实时状态契约（逐工具实时承载评估、实时物体观测）；Runtime 仅上报原始工具传感状态与统一场景几何。（来源：semantic-ability/r1pro-ability @ab04f30（2026-08-20）；semantic-simulation/mujoco-runtime @0396e35、@d00e63a；semantic-skill/robot-skill @66d9aa8）

## 制品升级顺序

1. Framework（semantic-server）与 Web/Studio；
2. Robot Bundle：经类型包构建的 `r1pro-mujoco` / `r1pro-fake`（内含 Robot SDK core/r1pro、AbilityFramework、Ability、Pilot、`semantic-robot-instance` 启动器与锁定 Python Wheel）；
3. Robot Skill：经 `publish-v050-mujoco-skills` 发布（需要 `SEMANTIC_ACCESS_TOKEN`），Robot Skill 以 `name@version` 精确引用（文档示例 `grasp-object@0.4.17`）；
4. Runtime Pack：plugin-mujoco（当前版本 0.4.0.dev0，`/healthz` 可见）；
5. Scene 资产：`semantic-scene` 执行 `git lfs pull` 后生效。

顺序依据：semantic-framework/scripts/refresh_v050_mujoco.py 的 build→activate→publish 流程与 docs/developer/quickstart 第 2、5、7 章制品引用。TODO(确认)：Bundle 内 `ability_py-0.4.0`、`semantic_r1pro_abilities-0.4.0.dev0` 与 Runtime Pack `0.4.0.dev0` 的版本号在 v0.5.0 正式发布时是否升位。
