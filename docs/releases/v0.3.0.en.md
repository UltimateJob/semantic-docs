## Scope

v0.3.0 focuses on conversational planning: users enter Plan Mode explicitly, deterministic scheduling is driven by explicit Workflow/Task/SubTask, and generic structured Interactions collect user input. Framework includes a built-in Semantic Map.

Simulation, Pilot, Robot Skill, AbilityFramework, and Robot execution **are not in this version**. (Source: v0.3.0 sections of semantic-framework/CHANGELOG.md and semantic-web/CHANGELOG.md)

## Added

- Explicit Plan Mode and conversational planning: plan generation, approval, and execution are explicit in Conversation and the workbench. (Source: semantic-framework/CHANGELOG.md v0.3.0; semantic-web @2876434, @d9ae3a6, 2026-08-09)
- Explicit Workflow/Task/SubTask planning and deterministic scheduling, including a real run chain and execution loop. (Source: semantic-framework @65e6930, @3e788bc, @ca68083, 2026-08-09)
- Eight structured Interaction types: persistent structured input and recovery, free-form fill for choice items, and Task SendScope. (Source: semantic-framework @0271042, @de0eda7; semantic-web/CHANGELOG.md v0.3.0)
- Built-in Semantic Map: `simulation_map` / `real_map` isolation and 2D/3D map workbench. (Source: semantic-framework/CHANGELOG.md v0.3.0; semantic-web/CHANGELOG.md v0.3.0)
- Plan and Semantic Map HTTP APIs: v0.3 plan and map interfaces, with task context and map version semantics stored. (Source: semantic-framework @522cbfd, @489bfb4, @c07803c, @d1e1835, 2026-08-09)
- Map Inspector editing: object editing and evidence moved into Inspector, in-place property forms, pose editing, and 2D pan restore. (Source: semantic-web @9fb2a26, @3cb2ae7, @8d86b0b, 2026-08-09)

## Breaking changes

- Removed the v0.2-only public fixture server and local component manifest delivery. (Source: semantic-framework @11ab195, 2026-08-09)
- Plan Mode replaces the old implicit planning entry. In-progress old Workflows/runs do not migrate automatically; finish the old plan before entering Plan Mode. (Source: semantic-web @6943fb2; semantic-docs @1282132, 2026-08-09)

## Configuration migration

- No new configuration fields. Database compatibility follows v0.2.0: development databases do not promise compatibility with unpublished experimental schemas. On `STORE_SCHEMA_INCOMPATIBLE`, back up first, then run `semantic init --reset-data`. (Source: semantic-framework/CHANGELOG.md v0.2.0 data notes)

## Action Schema changes
